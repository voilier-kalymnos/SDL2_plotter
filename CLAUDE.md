# CLAUDE.md

Guidance for AI coding agents (and humans) working in this repository.

## What this is

**SDL2 Plotter** is a marine chart plotter in Rust: a single binary that renders local MBTiles raster charts with SDL2, follows the boat using live data from a Signal K server over WebSocket or from an NMEA 0183 stream over TCP or UDP (`[input] source`), shows AIS targets, and lets the navigator keep routes, waypoints, a track and distance measurements. It also serves the screen as an MJPEG stream so a tablet in the cockpit can watch. Deployment target: a Raspberry Pi running a minimal Linux without a desktop, at the chart table, 24 hours a day for weeks. Windows is a development platform only.

- **Build, run, configure:** [`README.md`](README.md). Windows specifics and verified build numbers: [`WINDOWS_BUILD.md`](WINDOWS_BUILD.md).
- **Known debt:** deepening work in progress is tracked on the wayfinder map [`docs/wayfinder/architecture-deepening.md`](docs/wayfinder/architecture-deepening.md), charted from [`docs/architecture-review-2026-11-23.html`](docs/architecture-review-2026-11-23.html).

> **It is a safety instrument.** The person at the chart table may be tired, wet and relying on this screen in the dark. Every design choice below follows from one rule: the chart must keep drawing and the boat must keep moving on it, whatever else fails.

## Golden rules

- **Never block the render thread.** The SDL main loop (`app.rs::main_loop`) handles input, draws and sleeps 16 ms, in one thread. Anything that can take more than a millisecond (decoding, encoding, network, disk) runs on a worker thread and talks to the loop through a channel the loop drains once per iteration. Tile loading, JPEG encoding and Signal K already work this way; follow those patterns.
- **Degrade, never exit.** No Signal K server, no chart tiles at the minimum zoom, an unbindable streaming address, a corrupt `state.json`: each one logs a WARN or ERROR and the app carries on with a fallback. A `?` in startup or the main loop that would quit the app needs a reason you can defend to a sailor.
- **Validate every coordinate at the boundary.** Longitude in -180..=180, latitude in -90..=90, both finite, before anything is stored or drawn. Signal K deltas, GPX and JSON files and user clicks are all boundaries. Coordinates are `(lon, lat)` tuples everywhere; see "Coordinate order" under Conventions below.
- **Every file the app writes (`default/`, `export/`, GPX included) goes through `geo_data::atomic_write`** (temp file, sync, rename). Build the contents in memory, then one call. Power cuts mid-write are normal on a boat.
- **Leave the tree green.** `cargo build` with zero warnings and `cargo test` passing before every commit. Ship the test in the same commit as the change, at a public seam (see Testing).
- **Tests write to `std::env::temp_dir()`**, never to `default/`, `export/` or the repo.

## Working with code and the human

Think before coding. State your assumptions out loud. If the request is ambiguous, ask. If a simpler approach exists, push back. Stop when you are confused, name what is unclear, do not just pick one interpretation and run.

Simplicity first. Write the minimum code that solves the problem. No speculative abstractions. No flexibility nobody asked for. The test: would a senior engineer call this overcomplicated?

Surgical changes. Touch only what the task requires. Do not improve neighboring code. Do not refactor what is not broken. Every changed line should trace back to the request.

Goal-driven execution. Turn vague instructions into verifiable targets before writing a line. "Add validation" becomes "write tests for invalid inputs, then make them pass."

Write chat replies, code comments, commit messages and docs in ASD-STE-100 (Simplified Technical English) style. (log 
messages stay in French).
- Use short sentences, with one instruction or one fact each. Keep an instruction to 20 words or fewer.
- Use one word for one meaning. Use the plain word when there is one.
- Use the correct technical name (AIS, COG, MBTiles, TMS). Define an acronym the first time a reply or a doc uses it.
- Use no analogies or figures of speech. When the human asks for a simple explanation ("explain that simply", "ELI5"), give one concrete analogy, then go back to this style.
- In a chat reply, start with the result in one bold sentence. Then put the rest in short lists, steps or tables.

## Quality gate (run before finishing)

```bash
cargo fmt -- --check                        # no output: the tree is rustfmt-clean
cargo build 2>&1 | grep -c '^warning'      # must print 0
cargo test                                  # all pass; 6 benchmarks stay ignored
cargo clippy --all-targets 2>&1 | grep -c '^warning'   # must print 0
```

- Touched the renderer or the stream? Also run the benchmarks and put before/after medians in the commit message: `cargo test --release bench_ -- --ignored --nocapture --test-threads=1` (single-threaded, or the timings interfere; needs a chart in `assets/` or `map/`).
- Changed anything the user sees? Run it: `cargo run --release`, pan, zoom, change chart, close the window, then read the tail of `plotter.log`. "Tests pass" is not "it works".
- The tree is rustfmt-clean with default settings. Never mix a formatter-only change with a behaviour change.
- Clippy is clean. A lint that is wrong for this code gets a targeted `#[allow(clippy::...)]` with a one-line reason above it (see `ConfirmAction`), never a crate-wide allow.
- No `#[allow(dead_code)]` outside the one documented test-only field in `stream.rs`. Dead code is deleted, not silenced.

## Threads, channels and the frame

Four kinds of thread, all started at launch:

- **SDL main loop** (`app::main_loop`, inside `#[tokio::main]`): per iteration it syncs the view, polls SDL events, then drains each live channel into the session (`Track::record`/`tick` for positions with the checkpoint policy inside, `Session::on_boat` for the fix, `Session::set_ais`/`expire_ais` for targets), ticks the gesture recogniser for long presses, advances zoom animation, draws if `dirty`, sets the cursor, calls `prefetch_step(8)`, sleeps 16 ms. The loop holds no policy of its own: it drains, calls and marks dirty. Every 10 s it logs loop statistics. Set `self.dirty = true` after any change the user should see; nothing redraws otherwise. A window resize is applied at the top of the next iteration by `Plotter::resize`, which makes the chart texture again: anything new that holds the window size needs a `resize` called from there. No step of the loop ends it: an event, resize, frame or stream capture that fails goes through `diagnostics::Repeated::report` (logged once, then every thousandth time) and the loop carries on. Never add a `?` inside `main_loop`. Each iteration (`Plotter::iteration`) runs inside `diagnostics::survive`, so a panic costs that iteration only; the panic hook logs it through `record_panic`, throttled the same way.
- **Source task** (tokio), the one `[input] source` picks in `Plotter::new`; it never returns. `nmea0183::run`: TCP client (reconnect, 30 s read timeout) or UDP listener, publishing on each RMC, HDT, HDG or `!AIVDM` (GGA, GLL and VTG when no RMC came for 5 s). `signalk::run`: connects with retry, subscribes to the configured paths, decodes deltas through `apply_delta` into a `DeltaSummary`, and publishes `BoatState` (watch), track points (unbounded mpsc) and the AIS list (watch) only when they changed. Evicts AIS targets silent for 5 minutes at most once a second.
- **Tile loader** (`TileLoader`, one per `MBTilesRenderer`): own read-only SQLite connection, request channel in, decoded tiles out, drained by `prefetch_step`. A tile a frame needs before the loader delivers it is decoded on the main thread so frames are never partial.
- **MJPEG**: a non-blocking accept loop, a blocking thread per viewer, and one encoder thread fed by a capacity-one channel so a slow encode drops frames instead of queueing them.

`display` draws the chart texture, then collects `Shape`s from measurement, route, boat, AIS, track and waypoints in that order, plans them against the current `ChartView` and paints them in one call, then the night overlay and bottom bar, then captures for the stream, then top bar and dialog, then presents.

## Conventions & gotchas

- **Coordinate order.** Tuples are `(lon, lat)` throughout, including `AisTarget::position`, route points, `screen_to_gps` and every function in `gps.rs`. `gps.rs` is the only haversine: `distance_nm`, `distance_meters`, `bearing_deg`. Do not add a local copy; `mesure.rs` reports nautical miles and `track.rs` works in metres from the same functions.
- **The view is explicit.** `Session::sync_view()` derives the centre (boat while following, else `state.position`), the pan offset and the course-up rotation from state and pushes them into the renderer with `look_at`/`set_rotation`. It runs at construction, at the top of every loop iteration, after every `execute_action` and in `display`. `renderer.view()` returns a copyable `ChartView` snapshot of it: `to_pixel(lonlat)`, `to_lonlat(pixel) -> Option` (absolute screen pixels, longitude wrapped, `None` off the Mercator square), `nearest(points, pixel, radius)` for every hit test, `panned_center`, `contains`, `course_to_screen`. Input, hit tests, overlays, prefetching and `render_frame` all derive from that one view, so there is no render-order dependency and no "centre minus click" arithmetic anywhere. Change state, then call `sync_view`; never set the view directly.
- **SDL2_gfx colours go through `screen::gfx(color)`.** The sdl2 crate packs a `Color` as 0xRRGGBBAA, but SDL2_gfx reads the bytes in memory order, so on a little-endian machine (the PC and the Pi) red/alpha and green/blue swap: black and teal came out fully transparent. Plain SDL calls (`set_draw_color`, `fill_rect`) take `Color` as it is. The headless `Plotter` test reads back a pixel to prove it.
- **i16 drawing.** SDL2_gfx takes `i16`. Never cast a screen coordinate to `i16` yourself; `overlay::plan` culls markers and `Screen`'s private primitives clip every segment through `ClipRect`. Off-screen points wrap otherwise and draw phantom lines across the chart.
- **Pan offset.** `state.map_offset` is a pixel offset from the boat and only means something while a valid fix is being followed. With no fix (dev PC, GPS lost) or with follow off, a pan moves `state.position` and the offset stays zero. A pixel offset is a different distance at every zoom, so `ChangeChart`, `ZoomIn` and `ZoomOut` call `anchor_on_visible_center` first: it folds the offset into the position unless the boat is the anchor. Never drop or keep an offset across a zoom change without going through it.
- **Zoom and the chart file belong to the session, not the file.** `state.zoom` is a whole level; `Session::sync_view` asks `Catalogue::choose` for the file at `renderer.display_zoom()` rounded, not `state.zoom`: mid-animation a file deeper than the drawing would need a source image 2^levels the screen each way, which once cost a 57 s frame. `change_map` runs only when the answer changes (a file that fails to open is logged once and not retried) and keeps the zoom, view and animation, so a file can be shown past its levels. A file drawn more than about a level above its first level (only possible under a lock) would need a source image bigger than the texture; the renderer then draws background for it and skips its prefetch (`source_size`), never a huge image. `ZoomIn` stops at `Choice::zoom_limit`; below every file's first level `charts.default` shows. `available_zooms` is what one file contains and can have gaps; `source_zoom_for` picks the level to draw from. How a layer is chosen, the lock and photo stepping: `docs/photo-button-design.md`.
- **MBTiles rows are TMS.** `fetch_tile_bytes` flips `y` (`n - 1 - y`). Metadata `minzoom`, `maxzoom`, `center` and `bounds` are optional and the code copes without them. They are also often wrong (one real file declares maxzoom 14 and holds 15), and `type` says nothing about satellite files (every satellite file tested says `baselayer`), so the catalogue reads zooms from the tiles and takes roles from the user.
- **Signal K self context.** The hello message's `self` field identifies our own vessel; deltas for that context and for `vessels.self` are the boat, every other `vessels.*` is AIS. Without the hello, only `vessels.self` is recognised.
- **Streaming address.** A failed bind logs an ERROR and the app runs without the stream (`Streamer::start_or_disable`). The checked-in `plotter.toml` binds 127.0.0.1 so a dev machine starts; the boat's address goes in deployment config. On Windows an accepted socket inherits the listener's non-blocking flag; `serve` resets it, keep that.
- **Logging.** `diagnostics::record(level, message)` for everything an operator might need; levels are DEBUG, INFO, WARN, ERROR, PANIC. INFO is the default floor, `PLOTTER_LOG=debug` lowers it, 5 MB cap with one `.1` backup. The only `println!`/`eprintln!` allowed are the fallbacks in `diagnostics.rs` and `main.rs` for when the log file itself cannot be opened, and the `bench_*` tests; a release build on Windows has no console, so a print is a message to nobody.
- **Paths are relative to the working directory**: `default/`, `settings/`, `export/`, `assets/`, `plotter.log` and the chart `directory`. The files under `default/`, `settings/` and `export/` come from `app::Files::default()`; nothing else names them. Run from the repo root. Charts (`*.mbtiles`, `map/`) are gitignored; `WINDOWS_BUILD.md` says where to get test charts.
- **French.** Log messages and many comments are in French; identifiers mix French and English (`Mesure`, `Buttombar`, `restante`, `RAYON_TERRE`). Write new identifiers and comments in English and leave existing names alone unless the commit is a rename. Settling on one language is deliberately left for later.
- **Windows build.** `Cargo.toml` adds `use-vcpkg` and `static-link` to `sdl2` only under `cfg(windows)`; Linux resolves the same three features as before. Keep platform differences in `Cargo.toml` and `.gitattributes`, never in `#[cfg]` blocks in the drawing or data code.
- **Dependencies.** Access WebSocket types through `tokio_tungstenite::tungstenite`; there is no direct `tungstenite` dependency. `tokio` is used only for the source tasks (Signal K, NMEA 0183).

## Non-negotiables

- A saved file must never be able to stop the app from starting. `GeoFile::load`, `State::new` and `Catalogue::load` enforce it: bad values are rejected, the file is set aside with a `.corrupt` suffix, an ERROR is logged, and the app continues with an empty collection or defaults. Loaders therefore return the collection, not a `Result`.
- An index from saved state (`nav_id`, chart index, selection) is clamped or checked before use. `Route::active_waypoint` is the model.
- Track points are never dropped silently: `Track::record` checkpoints the first point at once, `Track::tick` every `checkpoint_interval_seconds`, `Track::close` on exit, and `ClearTrack` asks for confirmation. Time is passed in (`Instant`), never read inside, so the policy is tested.
- Course-up rotation applies to the chart and every overlay through the one `ChartView` that `plan` uses; nothing draws in unrotated chart space on its own.
- The MJPEG stream shows the chart, the bottom bar (whose layer name tells a viewer the chart area is a photo) and the collision banner, never the menus, dialogs, photo button, centre button or AIS details window, so a viewer cannot be confused by a half-open menu on the tablet.

## Adding things

- **A menu action:** add an `AppAction` variant with its `name()` in `action.rs`; add `entry("Label", AppAction::Variant)` to a `Menu` in `topbar.rs::MenuBar::new` (the entry carries its action, there is no string matching); implement it in `actions.rs::execute_action` on `Session`, with a test beside the others there. Destructive actions request a `Confirmation` and do their work in `apply_confirmation` (see `ClearRoute`).
- **A config field:** struct field with `#[serde(default)]` semantics, a `Default` value, a check in `AppConfig::validate`, the key in `default/plotter.toml`, and the README section. The round-trip and defaults tests in `config.rs` will catch a missing `Default`.
- **A persisted data file:** a record type implementing `geo_data::GeoRecord` and a `GeoFile<R>` owned by the collection; `load()` never fails and `save()` is atomic. Older files are migrated with `with_legacy_file` (a neighbour such as `.gpx`) or `with_legacy_shape` (an older shape at the same path); bump `FORMAT_VERSION` only with such a migration.
- **A Signal K path:** field in `SignalKPaths` with a default, subscribe it in `SignalKClient::subscribe`, decode it in `apply_delta`, extend the `DeltaSummary` if the loop must react, and add a case to the `apply_delta` test.
- **An overlay:** a `Shape` variant in `overlay.rs` (chart coordinates), its projection and culling in `plan` with a test, a `Draw` variant, and the private primitive in `screen.rs` that `paint` calls for it, clipping through `ClipRect` before any `i16` conversion and taking colours from `AppearanceConfig`. The data module gains a `shapes()`; it never sees `Screen`.
- **Background work:** a thread owning its resources, a channel in, a channel out, a `drain` called from the main loop, and a `Drop` that closes the channel and joins the thread. `TileLoader` is the template.

## Testing

Tests live in `#[cfg(test)] mod tests` beside the code. Test at public seams, named for the behaviour (`navigation_distance_includes_the_remaining_legs`), with expected values from an independent source (60 nautical miles per degree of latitude, not the function under test).

- **Seams that exist:** `overlay::plan` and every module's `shapes()`; `Track::record`/`tick`/`close` and `Session::on_boat`/`expire_ais` with injected `Instant`s; `GestureRecognizer` with injected `Instant`s; `Session` tools via the shared fixture in `session::test_support` (`session(zooms)`, or `session_with_charts(&[(name, zooms)])` for several catalogued files in one layer; `target_at`, `click`, `long_press`, `drag_to`); `ChartView::centred_on` for every pixel/position conversion and hit test, no chart file needed; `Session` (build it with a struct literal over `fixture_chart` and temp paths, see `actions.rs` tests) for every `AppAction` and confirmation; `MenuBar` for the menu geometry; `gps` free functions; `Catalogue::load` on a temp directory of hand-built MBTiles files (names, tiles, metadata and the settings file all chosen by the test); `GeoFile` and `Route::load`, `Track::with_checkpoint_interval`, `Waypoints::load`, `State::new` on temp files (including corrupt ones); `apply_delta`, `update_ais_target`, `retain_fresh` for Signal K; `nmea0183::Decoder::apply` and `LineSplitter` for NMEA 0183; `BoatState::expired` and `Session::expire_boat` with injected `Instant`s; `feed::take_change` with a dropped sender; `MBTilesRenderer` via `fixture_chart`, which writes a real MBTiles file with solid PNG tiles; `clip_segment` and `ClipRect` for drawing; `Logger` for the log; `listen`, `serve` and `Streamer::submit` for the stream, driven by a raw `TcpStream` client.
- **The whole app, headless:** `app::tests::the_main_loop_survives_a_failing_resize_and_retries_it` builds the real `Screen` and `Plotter` on SDL's dummy video driver (`sdl2::hint::set("SDL_VIDEODRIVER", "dummy")`, no display needed), with every file in a temp dir through `app::Files`, and drives `Plotter::iteration`. Keep it the one SDL test in the binary: SDL is set up once per process. Use it for loop behaviour (errors, resize, frames); logic still belongs on `Session` or in the module that owns the data, where it is tested without SDL.
- **No seam of its own:** `input.rs`, `render.rs` and the widgets. `input.rs` only translates events into gestures and `AppAction`s; a new editing behaviour goes on `Session` in `tools.rs` with a test.
- Benchmarks are `#[ignore]` tests named `bench_*`, printing a median; see Quality gate.
- Temp names in tests come from `test_support::unique_name()` (process id, clock and a counter): tests run in parallel and two can read the same clock value on Windows.
- A fixture file is deleted at the end of its test, so anything holding it open (a loader thread, a connection) must be dropped first. On Windows the delete fails otherwise.
